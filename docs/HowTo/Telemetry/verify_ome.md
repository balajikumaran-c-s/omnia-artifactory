# Verify OpenManage Enterprise Telemetry

## Overview

Verify the Vector-OME bridge that consumes matching OME Kafka topics and routes
the enabled metrics and log channels to Victoria sinks.

## Prerequisites

- Complete [Configure OpenManage Enterprise Telemetry](telemetry_from_ome.md).
- Configure OME to publish to the exported native Kafka endpoint.

## Procedure

On the Kubernetes VIP, inspect the Vector-OME deployment and pod:

```bash title="Run on: Kubernetes VIP"
kubectl get deployment vector-ome -n telemetry
kubectl get pods -n telemetry -l app=vector-ome
kubectl logs -n telemetry -l app=vector-ome --tail=100
```

When metrics are enabled, also inspect `vmagent-vector`; when logs are enabled,
inspect `vlagent-vector`:

```bash title="Run on: Kubernetes VIP"
kubectl get deployment vmagent-vector vlagent-vector -n telemetry
```

## Verification

The Vector-OME pod must be Running. Confirm the requested fields under
`sources.ome` are `deployed` and `bridges.vector_ome: deployed` in
`telemetry_status.yml`.

## Next steps

- Query VictoriaMetrics or VictoriaLogs using the endpoints generated by the
  [external Victoria utility](configure_external_victoria.md).
- Retain the [Kafka export](configure_external_kafka.md) used by OME.

## Troubleshooting

- **No matching topics are consumed:** Confirm OME topic names start with the
  configured `ome_identifier` followed by a period.
- **A Vector agent is absent:** Enable the corresponding Vector-OME channel and
  ensure its Victoria sink is supported by an enabled collection target.
- **The bridge pod is not Running:** Inspect its logs and the dedicated
  `vector-ome-user` Kafka credentials.
